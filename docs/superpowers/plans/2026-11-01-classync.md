# ClasSync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Flutter Android app + Flutter web dashboard that shows a weekly class routine, synced through Firebase, and fires silent vibrating alerts 5 minutes before each class plus an 8:00 AM gap-period reminder.

**Architecture:** One Flutter codebase builds both Android and web. The routine is one Firestore doc `routines/{uid}`. A pure function `buildAlerts(Routine)` turns the routine into weekly-repeating local notifications, which the phone schedules itself (no push server), so alerts work offline.

**Tech Stack:** Flutter (stable), Dart, Material 3, `firebase_core`, `firebase_auth`, `google_sign_in`, `cloud_firestore`, `flutter_local_notifications`, `timezone`, `flutter_timezone`, `file_picker` (web JSON upload).

**Spec:** `docs/superpowers/specs/2026-11-01-classync-design.md`

## Global Constraints

- Alerts: vibration on, sound off, high importance, `fullScreenIntent: true`. Never a sound.
- Next-class alert fires 5 minutes before block start. Gap alert fires at 08:00.
- Alert title format: `COURSE · TEACHER · ROOM` (middle dot `·`, teacher initials). Body: start time `HH:mm`.
- Tough blocks: body adds `Snacks before the class.`; notification `color` = tough warm color. No extra vibration.
- Gap alert body: `N gap periods today: 12:15–13:05, …` (en dash between times, comma-separated). Singular: `1 gap period today: …`.
- All empty periods on a class day count as gaps (leading, middle, trailing). A class day with zero classes gets no alerts. Days not in `days` get no alerts.
- Times stored as 24-hour `HH:mm`.
- Theme: Material 3, `ColorScheme.fromSeed`, rounded corners on cards, dialogs, buttons, inputs, grid cells (radius 16, buttons/chips 12). Default accent `blue`. Swatches: blue, indigo, teal, green, orange, pink, purple. Tough color must not be in the swatch list (use `Color(0xFFFFB74D)` amber-orange tone distinct from `orange` swatch seed `Color(0xFFFF9800)`; builder may pick another warm color if it reads distinct).
- Firestore rule: `routines/{uid}` readable/writable only when `request.auth.uid == uid`.
- Android only for mobile; no iOS work. Installed via APK.

## Review Focus

1. **Editing the routine twice must not leave duplicate alerts** — rescheduling cancels all first and uses stable IDs. Test in Task 3 (`ids are unique and stable`).
2. **Changing the period count** (5 → 6 periods, or removing one) must pad/truncate every day's row, not crash or misalign cells. Test in Task 2 (`withPeriods pads and truncates rows`).
3. **New user with no Firestore doc** sees an empty routine, not a crash. Test in Task 2 (`Routine.empty()`), handled in Task 4 repo.
4. **Import JSON that omits a day listed in `days`** is valid and treated as an all-empty row; teacher initials missing from `teachers` are allowed. Test in Task 2.
5. **A bad import must leave the current routine untouched** — validation runs before any write. Test in Task 2 (`invalid file returns errors`), enforced in Task 6 (save only on zero errors).

### Task 2: Routine model + JSON import validation

**Files:**
- Create: `lib/model/routine.dart`, `test/routine_test.dart`, `test/fixtures/routine.json`

**Interfaces:**
- Produces:
  - `class Period { final String start, end; }` (`HH:mm`), `int get startMinute`.
  - `class ClassCell { final String course, teacher, room; final bool tough; }`
  - `class Routine { final String accent; final List<String> days; final List<Period> periods; final Map<String,String> teachers; final Map<String, List<ClassCell?>> cells; }`
  - `Routine.empty()` — accent `blue`, days `[]`, periods `[]`, teachers `{}`, cells `{}`.
  - `List<ClassCell?> row(String day)` — returns the row, or a list of `periods.length` nulls when the day has no row.

### Task 3: buildAlerts (pure)

**Files:**
- Create: `lib/alerts/build_alerts.dart`, `test/build_alerts_test.dart`

**Interfaces:**
- Consumes: `Routine`, `Period.startMinute`, `Routine.row` (Task 2); `toughColor` (Task 1) is NOT used here — keep this file Flutter-free.
- Produces:
  - `class Alert { final int id; final int weekday; final int minuteOfDay; final String title; final String body; final bool tough; }` — `weekday` uses `DateTime.monday..DateTime.sunday` (1–7).
  - `List<Alert> buildAlerts(Routine r)`.

Rules: for each day in `r.days`: if the row is all null → no alerts. Merge consecutive non-null cells with equal course+teacher+room into one block (`tough` = any cell tough). Class alert at `startMinute - 5`; if that is negative, wrap to previous weekday (+1440). Title `'$course · $teacher · $room'`; body `start` (e.g. `09:30`), plus `'\nSnacks before the class.'` when tough. Gap alert if any null in row: minute 480, title `'Gap periods today'`, body per Global Constraints. ID: `weekday * 100 + periodIndex` for class alerts, `weekday * 100 + 99` for the gap alert (stable across rebuilds).

- [ ] **Step 1: Write failing tests** (using fixture from Task 2):
  - `sunday first alert`: Sun alert with `minuteOfDay == 9*60+25`, title `DM · SJ · 121`, body `09:30`, weekday `DateTime.sunday`.
  - `lab block merged`: Monday has exactly one alert for `JAVA lab · MA · 121` at 9:25; none at 10:20.
  - `tough body`: Monday lab body is `'09:30\nSnacks before the class.'`, `tough == true`.
  - `sunday gap`: gap alert at 480, body `'1 gap period today: 12:15–13:05'`.
  - `tuesday trailing gaps counted`: body `'2 gap periods today: 13:10–14:00, 14:05–14:55'`.
  - `wednesday no gap alert`: no alert with id `3*100+99`.
  - `off days silent`: no alerts with weekday Thu/Fri/Sat.
  - `all-empty class day silent`: set every Tue cell null → no Tue alerts.
  - `ids are unique and stable`: ids unique; `buildAlerts(r)` twice gives equal id lists.
  - `wraps before midnight`: period starting `00:03` → alert on previous weekday at minute 1438.
